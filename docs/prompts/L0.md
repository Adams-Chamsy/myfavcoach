# Prompts Claude Code — lot L0 (socle)

Quatorze prompts, dans l'ordre. **Un prompt à la fois.** Après chacun : tu lances la commande de
vérification, tu regardes le résultat, et tu ne passes au suivant que si c'est vert.

Si un prompt produit autre chose que ce qui est annoncé, ne corrige pas toi-même : dis-le-lui
avec le message d'erreur exact. C'est plus rapide et ça évite de mélanger deux sources de vérité.

**Avant le prompt 1**, mets dans le dépôt vide : `CLAUDE.md`, `docs/`, `design/tokens.json`,
`maquettes/` (les 7 HTML + les 4 fichiers d'outillage). Puis `git init` et un premier commit.

---

## P0.1 — Initialisation du dépôt

```
Initialise le projet. Lis d'abord CLAUDE.md en entier, puis docs/perimetre.md.

Crée une application Expo avec expo-router et TypeScript en mode strict, à la racine du
dépôt existant (ne crée pas de sous-dossier).

Structure exacte à créer, vide pour l'instant :
  app/            (routes)
  src/composants/ src/fonctionnalites/ src/services/ src/theme/ src/fixtures/ src/test/

Configure :
- TypeScript strict, chemins absolus depuis src/ (alias @/)
- ESLint + Prettier, avec une règle qui interdit les littéraux de couleur hexadécimale
  dans src/ et app/, sauf dans src/theme/
- Jest + @testing-library/react-native
- Les scripts npm listés au §6 de CLAUDE.md. npm run verif enchaîne
  tokens, lint, typecheck, test, test:a11y. Les scripts pas encore implémentés
  (tokens, test:a11y) sortent en succès avec un message "à venir".
- .gitignore, .env.exemple vide, .nvmrc

Ne crée aucun composant, aucun écran, aucune dépendance d'interface.
Termine par : la liste des fichiers créés, les dépendances ajoutées avec leur raison en
un mot, et la commande à lancer.
```

**Vérification :** `npm install && npm run verif && npm start` — l'application démarre sur un
écran vide sans erreur.

## P0.3 — Générateur de tokens

```
Écris scripts/build-tokens.mjs qui lit design/tokens.json et génère :
- src/theme/tokens.ts : un objet typé, thèmes clair / sombre / montre déjà aplatis
  (sombre et montre déclarent $extends : applique la surcharge à la génération, pas à
  l'exécution)
- src/theme/types.ts : les types dérivés (NomCouleur, NomEspace, NomTexte…)

Contraintes :
- Aucune dépendance externe, Node seul
- Les fichiers générés commencent par "// GÉNÉRÉ — ne pas éditer. Lance npm run tokens."
- Les valeurs numériques sortent en nombres, pas en chaînes
- Les styles typographiques sortent prêts pour React Native (fontFamily, fontSize,
  lineHeight, fontWeight, letterSpacing en nombres)
- Le script échoue avec un message clair si une référence {font.display} est introuvable

Branche npm run tokens dessus. Ajoute src/theme/ à .gitignore ? NON : les fichiers générés
sont commités, pour que le dépôt soit lisible sans lancer le script.

Écris un test qui vérifie que src/theme/tokens.ts est à jour par rapport à
design/tokens.json : il régénère en mémoire et compare. Ce test doit échouer si quelqu'un
édite le fichier généré à la main.
```

**Vérification :** `npm run tokens && npm test` — le test de fraîcheur passe. Modifie une
couleur à la main dans `src/theme/tokens.ts` : le test échoue.
