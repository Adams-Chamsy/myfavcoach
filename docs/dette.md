# Dette technique

Dettes créées volontairement pendant l'initialisation du projet (lot L0), à traiter au lot
indiqué.

| Dette | Raison | Lot de traitement |
|---|---|---|
| `npm test` tourne avec `--passWithNoTests` | `src/test/` est vide à l'initialisation ; sans ce drapeau, `npm run verif` échouerait tant qu'aucun test n'existe. À retirer dès les premiers tests écrits. | L0, dès la première primitive testée |
| `app.json` ne référence aucune icône ni écran de démarrage | Aucun asset de marque n'existe encore dans le dépôt ; en inventer un serait une donnée de contenu non fournie. | L0, quand les assets de marque arrivent |
| Node local (22.12.0) sous la version minimale de React Native (`^22.13.0`) | Contrainte de l'environnement de développement au moment de l'initialisation, pas du code. `.nvmrc` fixe la version cible. | Avant le premier `npm start` réel |
| `jest` figé en 29.x (et `@types/jest` avec) | `jest-expo` embarque des outils Jest 29.x en interne (`babel-jest`, `jest-environment-jsdom`, `@jest/globals` en `^29`) ; `jest` 30 casse au runtime (`clearMocksOnScope is not a function`). À réévaluer quand `jest-expo` supportera Jest 30. | L12 |
| Croix de suppression de `Chip` (16 px) en constante locale `TAILLE_CROIX`, pas en token | `design/tokens.json` n'a que `taille.icone` (24) ; docs/design-system.md §6 demande explicitement « croix 16 ». Même raison que les lignes de focus/échelle d'appui déjà résolues (`bouton.tsx`) : constante locale documentée plutôt qu'un ajout muet. | Quand `taille.iconePetite` (ou équivalent) sera ajouté à `design/tokens.json` |
| Hauteur du ratio `pleinCadre` d'`EmplacementImage` (400 pt) en constante locale `HAUTEUR_PLEIN_CADRE` | docs/design-system.md §7 fixe « plein cadre 400 pt de haut pour l'en-tête du profil coach », mais ce n'est ni un ratio ni un token existant de `design/tokens.json`. | Quand une taille dédiée (ex. `taille.enTeteProfil`) sera ajoutée à `design/tokens.json` |
| Durée de pulsation de `Squelette` (1200 ms) en constante locale `DUREE_PULSATION` | docs/design-system.md §6 demande « pulsation d'opacité 1200 ms » ; `mouvement.valeur` (600) est la seule durée voisine dans `design/tokens.json` et sert à autre chose (Progression). | Quand `mouvement.pulsation` (ou équivalent) sera ajouté à `design/tokens.json` |
| `previsualiserEtat` sur `Bouton` et `BoutonIcone` (force l'affichage de l'état pressé ou focus) | Ces deux états sont pilotés en interne par les événements `Pressable`, sans prop exposée ; la galerie (L0-00, section 4) doit pourtant les montrer côte à côte de façon statique, sans interaction réelle. Réservé au fichier `app/_galerie.tsx`, jamais utilisé par un écran produit. | Aucun — mécanisme définitif, à surveiller seulement si `Bouton` change de gestion d'état |
| `npm run test:a11y` n'existe pas encore (`echo` dans `package.json`) | Les critères de contraste de `BarreNavigation` (docs/ecrans/L0-02-coquille-coach.md, critère 3) sont vérifiés à la main (calcul du ratio WCAG réel, texte.surSombre à 70 % sur fond.inverse = 7,74:1, actif plein = 7,58:1), pas par un script automatisé. | P0.14, quand `test:a11y` sera écrit |
| Taille du logo de démarrage (64 pt) en constante locale `TAILLE_LOGO` (`app/index.tsx`) | docs/ecrans/L0-04-demarrage.md fixe « le M en Instrument Serif, 64 pt » ; `texte.display` (44), le plus proche, n'est pas 64 et n'a pas vocation à l'être (chiffre clé d'écran, pas logo). | Quand un token dédié (ex. `taille.logoDemarrage`) sera ajouté à `design/tokens.json` |
| `src/services/trousseau/trousseau.ts` n'expose que la lecture (`lireSession`) | L0-04 ne lit le trousseau qu'au démarrage ; l'écriture (connexion, déconnexion, rafraîchissement) dépend de la forme réelle de la réponse d'authentification, pas encore conçue. | L1, avec l'identité et les comptes |
